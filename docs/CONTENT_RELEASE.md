# Golden content release checklist and report

This report is derived from `src/content/catalog.js`. It describes local content
readiness, not launch, legal, account, payment, or deployment approval.

## Run it

```sh
node scripts/content-status-report.js
node scripts/content-status-report.js --json
node scripts/content-status-report.js --production
node scripts/content-status-report.js --scope authored --production
node --test scripts/content-status-report.test.js
```

Normal reporting exits **0** even when content is blocked: generating a report is
not approving a release. With `--production`, blocked or empty selections exit
**1**. Invalid arguments or a reporting failure exit **2**. The command writes to
stdout only and never changes sources, installs dependencies, or calls services.

The default gate includes every mapped first-year slot (`--scope catalog`). An
explicit `--scope authored` checks the 29 manuscript-backed local preview
candidates and leaves later outlines out of that gate. Both report formats still
show the entire catalog's coverage. A passing authored subset would not authorize
publishing designed sessions or claiming all five years are complete.

Output contains no run timestamp, uses stable ordering, and recalculates every
release gate. Reversing source-provider order produces identical report bytes.
`--json` includes per-door status, review, and voice distributions, blocking
reasons with affected counts by door, each authored/stale script and its source
references, and a deduplicated provenance inventory. Reasons overlap; their counts
must not be summed as a count of blocked sessions. Elective ranges do not inflate
session counts.

## What has to change before authored content passes

1. A Keeper reviews and signs each exact content revision; retain the reviewer,
   approval date, and evidence reference. No current session has that approval.
2. Resolve the older practice scripts listed below against the current sit
   ladder. Shortening a timer alone does not approve conflicting spoken words.
3. Obtain and document approved recording/voice rights for the same revision.
   Browser TTS in a local preview does not establish those rights.
4. Re-run `--scope authored --production` over the final catalog. The publishing
   workflow must verify the evidence itself; the gate validates required fields,
   not external signature authenticity.
